# @tessen-ui/styles

Layered CSS for Tessen. Internal package (`private`, never published, see [ADR 0015](../../docs/planning/13-architecture-decisions/0015-npm-namespace-provisional-no-publication.md)); docs and ADRs call it `@tessen/styles`. Decision: [ADR 0006](../../docs/planning/13-architecture-decisions/0006-styling-authored-css-layers.md).

## Use

```css
@import '@tessen-ui/styles'; /* layers + tokens (+ component CSS once it exists) */
@import '@tessen-ui/styles/reset.css'; /* optional */
@import '@tessen-ui/styles/base.css'; /* optional */
```

| Entry                | Contains                                                            |
| -------------------- | ------------------------------------------------------------------- |
| `.` (`index.css`)    | Layer order, all tokens (light, dark, density), component CSS       |
| `layers.css`         | Only the `@layer tessen.reset, ... tessen.utilities;` statement     |
| `tokens.css`         | Layer order + tokens, no components                                 |
| `reset.css`          | Modern reset in `tessen.reset`. **Opt-in**, never in the default    |
| `base.css`           | Body, headings, links, code and focus ring in `tessen.base`. Opt-in |
| `components/<x>.css` | One file per component (first ones arrive in F2)                    |

Every file is self-contained (tokens are inlined, no `@import`) and declares the layer order once. All Tessen rules live in layers, so unlayered consumer CSS always wins. Base selectors use `:where()` (zero specificity).

## Themes and density

Light, dark (`data-tessen-theme`, `prefers-color-scheme`) and density (`data-tessen-density`) are generated by `@tessen-ui/tokens` and re-exported here; see its README. There is no separate `themes/` source until brand themes or `data-tessen-contrast` need one.

## Source layout

`src/layers.css`, `reset.css`, `base.css`, and later `components/*.css`. `pnpm build` assembles `dist/`; the build fails if the layer order differs from the one in tokens. Tests check that every rule is layered and every `var(--tessen-*)` exists in the tokens.

Not built yet: `data-tessen-motion` and reduced-motion handling (F1-T05), component CSS (F2).
